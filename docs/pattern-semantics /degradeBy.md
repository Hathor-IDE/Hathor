# `degradeBy` (and `degrade`, `undegrade`, `undegradeBy`, `?` operator)

Randomly remove events from a pattern with a given probability. `0` removes nothing
(identity), `1` removes everything.

## What it does

`degradeBy(x, pat)` keeps each of `pat`'s events with probability `(1 - x)` and drops it with
probability `x`. `degrade(pat)` is shorthand for `degradeBy(0.5, pat)`. The mini-notation
operator `?` compiles to a `degradeBy` call (`hh?` → `degradeBy(0.5)`, `hh?0.2` →
`degradeBy(0.2)`).

**Implementation**:
- `packages/core/signal.mjs:745` `register('degradeBy', function (x, pat) { return
  pat._degradeByWith(rand, x); })`
- `:767` `degrade = register('degrade', pat => pat._degradeBy(0.5))`
- `:788` `undegradeBy` and `:816` `undegrade` (the complementary functions, described below)
- The underlying combinator `degradeByWith` at `signal.mjs:720`.

## Exact algorithm

`degradeBy` delegates to the registered-but-not-exported pattern combinator
`degradeByWith(withPat, x, pat)` (`signal.mjs:720`), using `withPat = rand` (a continuous
0..1 random signal). The underscore variants (`_degradeByWith`, `_degradeBy`) are the
un-patternified forms generated by `register` (arity > 1 → `pattern.mjs:1820`).

```
degradeBy(x, pat):
  return pat._degradeByWith(rand, x)

degradeByWith(withPat, x, pat):
  # turn pat into a pattern of constant functions: value v -> (_ => v)
  constFuncs = pat.fmap(v => (_) => v)
  # keep only the random haps whose value is strictly greater than x
  randMask   = withPat.filterValues(v => v > x)
  # apply: for each pat-hap (structure from pat), keep value where a rand-hap overlaps
  return constFuncs.appLeft(randMask)
```

Where:
- `fmap(f)` maps each value (`pattern.mjs:95`).
- `filterValues(pred)` (`pattern.mjs:615`) drops haps whose *value* fails the predicate.
- `appLeft(other)` (`pattern.mjs:189`) is the applicative that keeps structure **from the left
  pattern (`this` = the value pattern)** and pulls values from the right: for each left hap, it
  queries `other` over that hap's `wholeOrPart()`, intersects `part`s, and applies the left
  hap's (function) value to the right hap's value. Because the left value is a constant
  function, the surviving event's value is the original `pat` value.

So a `pat` event survives if and only if the `rand` signal's value at that event's time is
`> x`. Since `rand ∈ [0,1)` (see determinism below), the drop probability is effectively `x`.

### `undegradeBy` / `undegrade` (complements)

`undegradeBy(x, pat)` uses `rand.fmap(r => 1 - r)` as the mask (`signal.mjs:791`), i.e. it
inverts the random value. The docstring states the intended property: "Events that would be
removed by `degradeBy` are let through by `undegradeBy` and vice versa" (`signal.mjs:773`).
`undegrade` = `undegradeBy(0.5)` (`:816`). Because `rand` is a deterministic function of time,
`degradeBy(0.5, pat)` and `undegrade(pat)` are exact complements in practice.

## Edge cases and invariants

- `x = 0`: predicate `v > 0` is (almost) always true (`rand ≥ 0`; see below), so **everything
  is kept** — `degradeBy(0)` is the identity. This matches the intended "0 = 0% chance of
  removal" docstring (`:730`).
- `x = 1`: predicate `v > 1` is never true (`rand < 1`), so **everything is dropped** — 
  silence. "1 = 100% chance of removal".
- `x` may be a pattern (patternified) and even a continuous control pattern
  (`degradeBy(rand2.range(...), pat)`).
- The comparison is **strict** (`v > x`), not `≥`. At exactly `x` the event is dropped. This is
  a boundary worth preserving for exactness (it rarely matters audibly).
- `degradeByWith` also supports arbitrary `withPat` (e.g. `randrun`, custom signals), but
  `degradeBy` always uses `rand`.
- Formal identity/property in papers: the ICLC demo paper and repo do **not** state the
  `degradeBy 0 = identity` property explicitly; it follows from the implementation. Treat the
  property as derived-from-code, not paper-cited.

## Determinism notes — this is the important part

Randomness in Strudel is **not** from a shared PRNG state machine; it is a pure,
deterministic hash of the absolute query time (and an optional per-pattern seed). This is what
makes patterns pure functions of time (a core Tidal/Strudel principle — `[lc-iclc]` "Patterns
are pure functions of time"; `[alternate-timelines]` for the general model).

### `rand` (`signal.mjs:480`)

```js
rand = signal((t, controls) => getRandsAtTime(t, 1, controls.randSeed))
```

`signal(f)` (`signal.mjs:18`) produces a continuous Pattern whose single Hap has `whole =
undefined` and value `f(state.span.begin, state.controls)`. So `rand`'s value is computed from
the **begin time of the query span** `t` and the `randSeed` control.

### The generator: two modes (`getRandsAtTime`, `signal.mjs:279`)

```js
let RNG_MODE = 'legacy'            // default
getRandsAtTime(t, n, seed):
  return RNG_MODE === 'legacy'
       ? __timeToRands(t + seed, n)      // default
       : timeToRands(t, n, seed)         // 'precise'
```

**Legacy mode (default)** — `signal.mjs:254-274`:
```js
__frac(x)            = x - trunc(x)
__xorwise(x)         = ((x << 13) ^ x)  ^  ...   // xorshift
__timeToIntSeed(t)   = __xorwise( trunc( __frac(t/300) * 2^29 ) )
__intSeedToRand(x)   = (x mod 2^29) / 2^29
__timeToRands(t, 1)  = |__intSeedToRand(__timeToIntSeed(t))|
```
So the seed is derived from `t` (the query begin time) by: take `t/300`'s fractional part,
scale to 2^29, xorshift once, then map to `[0,1)` via `(x mod 2^29)/2^29`. For `n > 1` it
iterates xorshift forward. The docstring notes this "repeats every 300 cycles"
(`signal.mjs:293`), because only `frac(t/300)` is used.

**Precise mode** — `useRNG('precise')` (`signal.mjs:297`) uses a MurmurHash-based generator
(`signal.mjs:211-248`):
```js
_tToT(t)    = floor(t * 2^29)
_decorrelate(T, i, seed):
  low  = T & 0xFFFFFFFF ; high = floor(T / 2^32) & 0xFFFFFFFF
  key  = low ^ imul(high ^ 0x85ebca6b, 0xc2b2ae35)
  key ^= imul(i      ^ 0x7f4a7c15, 0x9e3779b9)
  key ^= imul(seed   ^ 0x165667b1, 0x27d4eb2d)
randAt(T, i, seed) = murmurFinalize(_decorrelate(T, i, seed)) / 2^32
```
with `i` an index (0 for `n==1`) and `murmurFinalize` the standard avalanche finalizer
(`signal.mjs:211-219`, cites smhasher's MurmurHash3). The comment `signal.mjs:226` says the
`_decorrelate` step is "Used to decorrelate nearby T, i, and seed prior to hashing".

### Where the sample is taken, and why two `degradeBy` calls can be correlated

Because `degradeBy` uses `rand` as a continuous signal sampled at the **absolute query begin
time** `t`, *two `degradeBy` calls at the same time and same `randSeed` sample the same
random value* and are therefore correlated. The `seed` control is the explicit escape hatch.

`seed(n, pat)` (`signal.mjs:466`) wraps the pattern with `withSeed(() => n, pat)`
(`signal.mjs:445`), which overrides `state.controls.randSeed` to `n` before querying. The
docstring (`signal.mjs:454-457`) states the rationale: "Normally, random signals depend on
time, so two patterns at the same time will have the same random values. Specifying a new
seed changes the signal output by `rand`. This also affects other functions that use
randomness, like `shuffle` and `sometimes`."

So:
- **Depends on:** absolute cycle position / absolute time `t` (both modes), and an
  instance-specific salt only when `seed(n)` is applied (it sets `randSeed`, which feeds
  either `t + seed` in legacy mode or the `seed` hashing lane in precise mode).
- **Does NOT depend on:** the pattern's own internal structure or event index. The value is
  sampled *per event at that event's own begin time*: in `degradeByWith`, `appLeft`
  (`pattern.mjs:189`) re-queries `randMask` with `state.setSpan(hap_func.wholeOrPart())`
  for each discrete event, and `signal` computes its value from `state.span.begin`
  (`signal.mjs:19`). So two events at different times sample `rand` at their own begins and
  get independent-ish draws; the survival of one event is not tied to the pattern's structure,
  only to `t` (and `randSeed`).

The requirement that **multiple independent `degradeBy` calls be uncorrelated** is the reason
the mini-notation `?` operator assigns each occurrence its own tiny time offset. In
`mini.mjs:11` there is a module-level `const randOffset = 0.0003;`, and the `op_degrade`
grammar rule increments a parser counter `seed` per `?` (`krill.pegjs:156-157`), producing
`{ amount, seed }`. The builder then (`mini.mjs:44-48`):
```js
pat = reify(pat)._degradeByWith(strudel.rand.early(randOffset * op.arguments_.seed), op.arguments_.amount ?? 0.5)
```
`rand.early(d)` shifts the random signal earlier by `d` cycles (`early` = `withQueryTime(t => t
+ d)` + `withHapTime(t => t - d)`, `pattern.mjs:2228`). So each successive `?` samples `rand`
at a slightly different time (`t + k·0.0003`), decorrelating the coin flips. This is exactly
what the test "supports multiple independent uses of the random choice operator" checks
(`mini.test.mjs:151-191`): `[a|b] [a|b]` must yield ~25% each of `aa/ab/ba/bb` (independent
choices), verified with a binomial confidence interval. (That `|` operator is a *choose*,
compiled via the `rand` alignment and the same seed-offset mechanism — `mini.mjs:112-118`.)

## Known deviations / gotchas

- **Default RNG is 'legacy'** and repeats every 300 cycles (`signal.mjs:251-297`); results are
  therefore periodic over a 300-cycle window, not i.i.d. long-run. `useRNG('precise')` removes
  that periodicity. A port must choose and document which mode it replicates.
- Legacy mode's `+ seed` is added to `t` *before* the frac/300 scaling (`getRandsAtTime`:
  `__timeToRands(t + seed, n)`), so in legacy mode the seed acts as a **time offset**, not an
  independent hash input (as it is in precise mode). This is a real behavioral difference
  between modes.
- `rand`'s value range is `[0, 1)`; the strict `> x` comparison means `x` near 0 still drops
  the measure-zero point value (negligible in practice).
- The `undegradeBy` complement property holds because `degradeBy`/`undegradeBy` both sample
  `rand` (one via `r`, one via `1 - r`) at the same time; if you layer them with different
  seeds the complementarity breaks (by design — that's the point of seeding).
- `degradeBy` is documented with `0 = 0% chance of removal, 1 = 100%` (`signal.mjs:730-731`)
  and the mini `?` default is `0.5` (`krill.pegjs:156`, `mini.mjs:47`).
